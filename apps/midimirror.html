MidiMirror

Build what your MIDI controller does, without writing a line of Python.

Getting a MIDI controller to do what you actually want in Ableton Live means either settling for whatever its factory script decided, or writing a Remote Script in Python. MidiMirror is the third option. Double-click a knob on screen, pick what it should do, and it does it. Build your own modes, put two jobs on one key, then generate a real Remote Script for your controller and use it like any other. The window stays open as a live mirror of the hardware, every control labelled with what it reaches right now.

A controller you design yourself

Double-click any control and choose its job from a page that matches what it does now: a mixer function on this strip or a named track, a parameter of the selected device by position or by name, an envelope stage found by name on whatever instrument is in front of it, or one exact parameter on one exact device on one exact track, written out in full.

Your own modes. The three that ship (Device/Track, Mixer/Sends, Free) are a starting point, not a limit. Add modes, rename them, delete them. A new one starts empty and every control in it is yours to assign. Assignments belong to the mode you made them in, so a knob can do one thing while you are mixing and something unrelated while you are sound designing.

Holds and combos. A key can do one thing on the tap and another when held, edited separately. Two keys pressed together can do a third thing. You can also give a control a key on your typing keyboard.

Then generate the script. Name your controller and MidiMirror writes a real Remote Script package into Live's User Library under that name, so "Launch Control XL" turns up in Live's Control Surface list as its own entry. Everything you built comes across: assignments, labels, holds, modes, combos, the layout and the learned MIDI addresses. Generating again later rewrites the script and leaves your configuration alone.

Only the Akai MIDI Mix ships with a ready-made script, but any controller can be taught. Press Learn on a control, move the real knob, and its true address is recorded. Hide what your panel does not have, move what sits elsewhere, add what it has and the MIDI Mix does not.

The drop

Press one key and the panel remembers where every knob and fader is standing. Build the track up however you like, sweep the filters, ride the sends, push it all into the red, then press the same key again and the whole thing snaps back at once.

While something is stored, every control that took part carries an orange mark at the value it will return to, a pip on a knob's ring or a line across a fader's well. That answers the only question worth asking mid-take: if I hit it now, what happens?

Hold the drop key to re-aim it. Keep it down, move whatever you want the return to land on, let go, and that is the new snap-back point. Nothing moves on the way in or out, so you can change where a drop returns to in the middle of a take without ever passing through the sound of the old one.

The drop follows the parameters it was taken from rather than the controls, so changing mode, bank or track in between does not confuse it.

What it does

  • Device lock. Pin the blue hand to one device and go on selecting other tracks without your knobs following. Which device you are editing becomes a decision you make rather than one the selection makes for you.
  • Instrument mode. Device mode follows the selected track's instrument instead of the blue hand, so the knobs land on the synth every time you change track.
  • Layers over modes. Tap a bank key and one knob row becomes the selected track's sends, or the four utility devices every track carries. Everything else on the panel stays where it was, which is what makes it a layer rather than a mode.
  • Ordered device control. The same knob does the same job on every instrument: cutoff, resonance and filter envelope first, then the device's own parameters, with the two amp and filter envelopes on the faders. Those are found by reading parameter names, so they are exact on Ableton's instruments and best-effort on VSTs that label their filter section.
  • Free mode hands every control to Live's own MIDI map on its own virtual port, so you can MIDI-learn anything without the script in the way.
  • Every knob, labelled, live. The mirror shows what each control reaches right now, not what it was mapped to when you set the template up. Hover for the full address, the name it is listed under, and the gestures it answers to.
  • It catches moves the MIDI stream cannot see. Automation, a plugin's own window and preset changes all move parameters without touching the panel. Values are compared at Live's display tick and pushed when they differ, so the mirror stays honest.
  • Pickup. A knob does nothing until it passes the value it is taking over, which is what stops a jump when you switch modes or recall a drop.
  • Transport on screen, for hardware like the MIDI Mix that has no transport keys at all. Play, stop, session record and capture, showing what Live is doing rather than what you last clicked.
  • It reads Live's own MIDI map. Live exposes no API for "what is CC 16 mapped to?", and never has. So for the knobs you hand-map yourself, MidiMirror reads the saved .als and recovers them from the set itself. The honest caveat: that file is only as current as your last save, so the app shows you the file's age alongside what it found.
  • Undo, saved setups and a live reference. One undo history over assignments, layout edits and learned MIDI alike. Name and switch between setups. A "This setup" page lists every control in every mode with what it does and the note or CC it sends, built by the script rather than written down, so it is right whatever you have changed.

Why standalone

MidiMirror runs as its own app, not a plugin, and reaches Live only through the Remote Script it generates — the same route any hardware controller's own script uses. That separation is deliberate — if Live crashes, MidiMirror and your panel layout are untouched, and if MidiMirror hits a snag, Live keeps running the set. Two independent programs talking over MIDI beats one process that takes both down when either one stumbles.

Requirements

Ableton Live is required. This is the one tool in the range that does not work with any other DAW, and it is worth being blunt about why. Parameter names, the modes, the addressed device and the lock all come from a Remote Script, and only Live loads Remote Scripts. Without Live the app could show you where your knobs are physically sitting and nothing about what they do, which is the entire point.

macOS for the mirror app. An Akai MIDI Mix is the one controller with a ready-made script; any other controller works once you have learned its addresses and generated a script for it, which the app does for you.

Setting it up

1. Install the app, and let it place its Remote Script in Live's User Library on first launch.
2. In Live: Preferences → Link/Tempo/MIDI, and pick MidiMirror as a Control Surface with the MIDIMIX as its input and output.
3. Open the mirror on your second screen.

Move a knob and its name appears. Select a different device and every label follows.
